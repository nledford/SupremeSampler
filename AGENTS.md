# AGENTS.md

## What this is

SupremeSampler is a macOS app that generates Photo Supreme (IDimager) `.psc`
scripts for random-sampling photos out of a large catalog (millions of items), filtered by metadata (rating, category/keyword, etc.). It reads the
Photo Supreme SQLite catalog directly, read-only, to build filters and
preview results before a script is ever generated or run.

It does not write to the catalog, and does not run scripts itself — it
generates `.psc` source for the user to review and run inside Photo
Supreme's own Script Studio.

## Stack

- Swift + SwiftUI, macOS 14+.
- Real Xcode project (`SupremeSampler.xcodeproj`), generated by
  [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`.
  **`project.yml` is the source of truth and is tracked in git; the
  `.xcodeproj` itself is gitignored and regenerated on demand** (`just
  generate`, or automatically via `just build`/`test`/`run`/`xcode`).
  This avoids Xcode's noisy `pbxproj` diffs in version control — add new
  files/targets by editing `project.yml`, not by dragging files into
  Xcode (Xcode edits to the project structure will be lost on the next
  `xcodegen generate`; source file edits are unaffected).
- SQLite access: read-only, from a local file. (No dependency added yet;
  GRDB.swift is the planned choice when catalog-querying work starts —
  add it as a Swift Package dependency in `project.yml`.)

## Commands

Run `just` for the full list. Common ones:

- `just build` / `just run` / `just test`
- `just generate` — regenerate `SupremeSampler.xcodeproj` from `project.yml`
- `just xcode` — regenerate, then open in Xcode

## Photo Supreme interpreter quirks (load-bearing for script generation)

Photo Supreme's script interpreter is closed-source, embedded, and does
not support the full Delphi/Object Pascal language. These were confirmed
by direct testing in Script Studio and must be respected by any code the
generator emits:

- `Random` takes **no parameters** (`Random: Extended` in `[0, 1)`, not
  `Random(N: Integer): Integer`). Scale manually: `Trunc(Random * N) + 1`.
- `try...except...raise` is **not supported**. Only `try...finally` is
  used anywhere in working scripts.
- A `const` section apparently cannot mix multiple declarations with
  comments interleaved between them the way a normal Delphi file would;
  the working pattern is a separate `const` keyword before each constant,
  with its explanatory comment above the `const` line.
- `TidElement.Data` (`TObject` in the public API, concrete class
  undocumented) can be assigned to a `Variant` and late-bound
  (`.Clear`, `.Items.SomeProp`) successfully — confirmed working, not a
  guess.
- The public PasDoc API docs (https://repository.idimager.com/documentation/)
  do not cover everything actually used in working scripts (e.g.
  `PublicBroadCast`, `PublicBroadCastRequest`, `TDBXOMDataSets` are
  undocumented but real). Don't treat "not in the docs" as "doesn't
  exist" or vice versa — verify by compiling in Script Studio.
- Random-rowid sampling (draw random rowids, keep the ones that match)
  beats `ORDER BY RANDOM() LIMIT N` by roughly 10x on the real catalog,
  because the latter still evaluates `RANDOM()` for every row that
  matches the `WHERE` clause. Any generated filtered-sample script should
  use the same technique, with the oversample factor and `WHERE` clause
  applied to both the row-count/max-rowid query and the sampling query.

## Safety

- Read-only, always. Never write to the live catalog from this app.
  See `write-behavior.md` in the docs directory above for why (no
  foreign keys, only triggers; cascading deletes; non-stable rowids).
- Photo Supreme's catalog file changes while the app is open (WAL mode) —
  open connections read-only (`mode=ro`) and don't assume a stable
  snapshot across queries.
